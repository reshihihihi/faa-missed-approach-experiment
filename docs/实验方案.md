# 复飞信息结构化提取实验方案

## 一、文档定位

本文档用于说明**当前正式实验口径**，即基于 `v2604_100` 的 100 样本实验方案。

为避免歧义，本文档不再采用早期 10 样本预实验的编号与结果口径。当前正式口径统一为：

- `O`：CIFP 参考基准
- `A`：OCR + 规则抽取
- `B`：OCR + LLM
- `C`：图像直读 + 多轮单问题 QA
- `D`：图像直读 + 单轮整体 JSON 抽取
- `E`：图像直读 + 问卷约束后输出 JSON

说明：

- `pilot_10` 仅用于早期流程验证和 prompt 调整，不作为最终结论依据。
- 本文档描述的对象是**正式 100 样本实验**。

## 二、实验目标

本实验面向 FAA 进近航图中的 missed approach instruction，目标是从航图中自动抽取结构化复飞信息，并比较不同技术路线的效果。

实验核心关注以下字段：

- `climb_altitude`
- `turn_direction`
- `holding_required`
- `holding_fix`
- `waypoints`

辅助字段包括：

- `raw_instruction`
- `initial_track`
- `turn_trigger`
- `holding_details`

其中，正式主指标只围绕前五个核心字段统计。

## 四、实验路径定义

### 4.1 路径 O：CIFP 参考基准

路径 `O` 不作为待比较方法，而是参考基准。

其作用是：

- 从 FAA CIFP 中定位对应程序的 missed approach 段
- 将 424 编码内容转换为可核对的结构化 JSON
- 为 A/B/C/D/E 提供统一对齐对象

需要强调：

- `O` 是当前实验中的**参考真值基准**
- 它不是“绝对无误的自然语言真理”，而是基于 FAA CIFP 结构化程序编码得到的统一比较对象
- 当图面表达与编码表达粒度不完全一致时，应以实验预先确定的归一化和对齐规则为准

### 4.2 路径 A：OCR + 规则抽取

流程：

- 使用 `PaddleOCR` 对航图执行 OCR
- 提取 OCR 文本
- 基于规则、正则与字段逻辑输出结构化 JSON

特点：

- 可解释性强
- 便于定位错误来源
- 受 OCR 顺序、噪声文本和复杂版面影响较大

### 4.3 路径 B：OCR + LLM

流程：

- 使用与 A 相同的 `PaddleOCR`
- 将 OCR 文本输入大模型
- 由模型完成语义整理并输出 JSON

方法学意义：

- 与 A 共享同一 OCR 输入
- 可以更清晰地比较“规则抽取”和“LLM 文本抽取”的差异

### 4.4 路径 C：图像直读 + 多轮单问题 QA

流程：

- 直接输入航图图像
- 不一次性输出整份 JSON
- 针对关键字段逐个提问
- 再将多轮问答结果汇总为统一 JSON

当前重点字段包括：

- `raw_instruction`
- `climb_altitude`
- `turn_direction`
- `holding_required`
- `holding_fix`
- `waypoints`

方法学意义：

- 通过字段级拆分，减少整体式抽取中的字段串扰
- 重点检验是否能够降低过预测

### 4.5 路径 D：图像直读 + 单轮整体 JSON 抽取

流程：

- 直接输入航图图像
- 由多模态模型整体理解图文内容
- 单轮输出完整 JSON

方法学意义：

- 代表“图像直接理解 + 整体抽取”的基线方案
- 用于与 C 的字段分解式方案做直接对照

### 4.6 路径 E：图像直读 + 问卷约束后输出 JSON

流程：

- 直接输入航图图像
- 先通过约束式问卷确认关键判断
- 再输出最终 JSON

方法学意义：

- 代表“整体式抽取 + 更强输出控制”的方案
- 用于观察提示约束是否能抑制自由发挥与过预测

## 五、统一输出 Schema

所有路径最终输出均需对齐到统一 JSON Schema。

### 5.1 核心字段

| 字段名 | 含义 | 备注 |
|--------|------|------|
| `raw_instruction` | 复飞原始指令 | 图面原文或模型提取文本 |
| `climb_altitude` | 爬升高度 | 统一为英尺数值 |
| `waypoints` | 复飞中涉及的 waypoint / fix 列表 | 航点名统一大写 |
| `turn_direction` | 转弯方向 | `LEFT / RIGHT / NONE / unknown` |
| `holding_required` | 是否存在等待程序 | `true / false / unknown` |
| `holding_fix` | 等待点 | 无等待时可为 `null` |

### 5.2 扩展字段

| 字段名 | 含义 |
|--------|------|
| `initial_track` | 初始航迹 |
| `turn_trigger` | 转弯触发条件 |
| `holding_details` | 等待程序细节 |

### 5.3 统一规范

- 航点名统一大写
- 高度统一为英尺数值
- 所有核心字段必须存在
- 无值但确定不存在时使用 `null`
- 无法确认时使用 `"unknown"`

## 六、归一化与异常处理

### 6.1 归一化处理

在评估前，输出结果统一进行如下处理：

1. 航点名大小写规范化
2. 高度值标准化
3. 枚举字段表达归一
4. `null` / `unknown` 标准化
5. waypoint 集合按统一规则比较

### 6.2 异常处理原则

所有路径统一遵循相同的异常处理规则，不允许在实验后根据结果表现临时修改。

主要原则：

- 可机械修正的格式问题先标准化，再参与评估
- 字段缺失视为漏检
- 字段存在但值错误视为错误预测
- 输出为 `unknown` 而参考基准可明确给出时，按漏检处理
- 结构错误或无法解析时，按失败样本处理

## 八、评估方法

### 8.1 当前实际使用的主指标

正式实验当前实际使用的指标包括：

- `Scalar Precision`
- `Scalar Recall`
- `Scalar F1`
- `Waypoint Precision`
- `Waypoint Recall`
- `Waypoint F1`
- `Mean Waypoint Jaccard`
- `Waypoint Exact Rate`

说明：

- 这些指标以统一基准 `O` 为参考
- 当前正式实现并**没有**单独启用“复飞动作链完整率”这一额外结构级指标
- 若未来增加新的结构级指标，应在文档与脚本中同步更新

### 8.2 错误分析

错误分析围绕以下几类模式展开：

- scalar 字段的漏检、错值、误报
- waypoint 的全漏、缺点、加点、纯误报
- 同一样本上的组合错误模式

该部分由：

- `error_analysis.py`

统一生成。

## 十、当前方法结论口径

在当前 100 样本正式实验下：

- `C` 是当前综合表现最好的方案
- `D` 与 `E` 非常接近
- `B` 明显优于传统 OCR + 规则方案 `A`
- 图像直读路线整体优于 OCR 路线

当前剩余的主要问题集中在：

- `waypoints:spurious_only`
- `holding_fix:spurious_prediction`
- `holding_required:false_hold`
- `turn_direction:hallucinated_turn`

因此，下一阶段优化重点应继续放在：

- 抑制过预测
- 提升字段边界判断
- 降低 waypoint 和 holding 相关误抓

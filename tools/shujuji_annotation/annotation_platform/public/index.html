目标不是重新理解整张航图，而是确认“图上的框”能不能支持 PR #28 最大 JSON 里的字段。

  1. 最快路径。如果只是想用最少操作完成初校，可以先点“快速确认本图已有候选”，再只处理简化操作区剩下的缺证字段。
  2. 先点一个框。看“当前框”里的中文说明，确认这个框的边界是否合理。
  3. 看框的位置。大框可以覆盖整块区域；红色小框必须贴紧单个高度、箭头、fix、radial、holding 或距离文字。

  5. 看“PR #28 JSON 对齐/证据覆盖”。优先处理这里显示缺证的 present 字段；这些才是还缺人工证据的重点。
  6. 如果缺字段但图上已有框。点那个正确的框，再到“候选目标字段”里找到相同航段/字段，点“挂到当前框”，再回到“字段对应”点“确认对应”。
  7. 如果缺字段且没有框。在上方选择合适框类型，点“框选新增”，贴紧画框，然后在候选字段里点“挂并确认”。
  8. 不用管折叠的自动字段。“无需画框字段 / 自动状态”表示该航图本来没有，或来自 424 编码状态，默认不用人工操作。
  9. 最后保存。当 present 证据覆盖接近 100%，明显错误都处理完后，点页面右上角“保存人工校准”。
可以直接确认：框内能清楚看到对应值，例如 MUDRE、3000、R-243、holding 图形。
不要确认：框太大框到无关内容、值不在框内、航段或字段对不上。
不确定：点“不确定”，备注写一句原因，不要随手删除可能有用的证据。

核心标准：一个 accepted 映射必须回答清楚三件事：第几个航段、什么航段类型、最大 JSON 的哪个字段。

一、这个页面分成哪四个区域

            
左侧样本列表：选择 10 张 Pilot 航图，查看样本标签，例如 simple、holding、multi_leg、ocr_hard、anomaly。

            
中间航图区域：查看原始航图和自动预标注框。这里负责看框是否圈对、移动框、新增框、拖拽调整框位置。

            
右侧检查详情：查看当前框、字段对应、PR #28 JSON 证据对齐、候选目标字段。这里负责判断“这个框能证明哪个航段的哪个字段”。

            
最右简化操作区：只显示最少操作路径、待确认候选、缺证字段和保存入口。新手优先看这里。

          


          

            
二、新手最少操作流程

            
    
              
  1. 选图。先在左侧点一张航图。建议按列表顺序一张一张做，避免漏图。
    2. 
              
  2. 先看最右侧“简化操作区”。它会告诉你当前还有多少“待确认候选”和“缺证字段”。如果不知道下一步做什么，优先看这里，不要先钻进 JSON。
    3. 
              
  3. 粗看三个关键区域。在中间航图上先确认三类大框：上方复飞文字大框、平面图复飞相关大框、下方复飞细节总框。大框只要求覆盖完整相关区域，不要求拆成很多小框。
    4. 
              
  4. 快速确认已有候选。如果预标注框看起来基本合理，可以点“快速确认已有候选”。这一步会把已经自动挂好的候选字段批量设为 accepted，用来减少人工点击。
    5. 
              
  5. 误点处理。如果你点完快速确认后发现不对，立刻点“撤销快速确认”。撤销后再逐个框检查，不要直接保存。
    6. 
              
  6. 处理待确认框。点“跳到下一个待确认框”，页面会选中一个需要检查的框。看右侧“当前框”说明，确认框的位置和类型是否正确。
    7. 
              
  7. 确认字段对应。如果当前框确实能证明“字段对应”里列出的航段字段，就点“确认对应”或“确认本框并跳下一个”。一个正确对应必须说清：第几个航段、什么航段类型、最大 JSON 的哪个字段。
    8. 
              
  8. 处理缺证字段。如果最右侧还有“缺证字段”，点该字段旁边的“去候选字段处理”。然后在图上找能证明这个字段的框。
    9. 
              
  9. 图上已有框时。先点中那个正确框，再到“候选目标字段”里找到同一航段、同一字段，点“挂到当前框”或“挂并确认”。随后回到“字段对应”确认。
    10. 
              
  10. 图上没有框时。在航图上方下拉框选择合适类型，例如 ALTITUDE_TEXT、FIX_TEXT、RADIAL_TEXT、HOLDING_ARC 等；点“框选新增”，贴紧对应符号或文字画框；再把候选字段挂到这个新框并确认。
    11. 
              
  11. 遇到不确定。如果你不能判断框是否支持该字段，点“不确定”，备注一句原因，例如“疑似对应但文字不清”或“航段可能不对”。不要为了凑 100% 随便确认。
    12. 
              
  12. 保存前检查。当待确认候选为 0，缺证字段尽量处理完，且没有明显框错位/字段错挂后，点击右上角“保存人工校准”。保存的是人工证据覆盖和字段对齐，不是独立 OCR 或 LLM 抽取正确率。
    13. 
            

          


          

            
三、框应该怎么判断

            
总体原则：框不是为了好看，而是为了给 PR #28 最大 JSON 中某个字段提供图上证据。能回答“它证明了哪个航段的哪个字段”才算有用。

            
上方复飞文字大框：用于覆盖航图标题附近的 MISSED APPROACH 文字说明。只要完整覆盖复飞文字说明即可，不需要把 climb、heading、fix、hold 等词逐个拆小框。

            
平面图大框：用于覆盖平面图中与复飞路径相关的整体上下文，例如复飞航迹、复飞 fix、等待图形、备用复飞 fix 小图等。它主要帮助理解路线，不直接替代下方细节小框。

            
下方复飞细节总框：用于圈住剖面图/下方小表格里专门描述复飞步骤的区域。这个总框可以稍大，但应尽量只覆盖复飞步骤区域，不要大面积框到跑道图、最低标准表、无关说明。

            
下方细节小框：高度、爬升箭头、转弯弧线、fix/navaid 名称、fix 符号、radial、track、heading、inbound/outbound、holding 时间、DME/距离等都应尽量单独小框。小框要贴紧单个符号或文字，能小不要大。

            
ALTITUDE_TEXT：框住高度数字，例如 3000、8700、11000、6500。不要把相邻 fix 名称或箭头一起框进去，除非数字和符号严重连在一起无法拆开。

            
CLIMB_ARROW / PATH_SEGMENT：框住代表爬升或转弯路径的箭头、弧线、折线。箭头和高度数字最好分开：箭头证明动作，高度数字证明 Q2 高度限制。

            
FIX_TEXT / NAVAID_TEXT：框住 MUDRE、CELTS、ZEXEL、EVVIS、COE、SGD 等名称文字。若同一格里还有 INT、VOR/DME、R-xxx，可以按字段需要拆成不同小框。

            
FIX_SYMBOL：框住菱形、三角形、navaid 符号等图形证据。文字和符号如果都清楚，最好文字一个框、符号一个框，方便后续判断。

            
RADIAL_TEXT / TRACK_OR_RADIAL_TEXT / HEADING_TEXT：框住 R-243、R-350、tr 284°、hdg 063°、heading 100° 等。注意不要把相邻的 fix 名称误当成 radial，也不要把 424 精确值的小数强行在航图上找出来，航图通常显示整数角度。

            
HOLDING_ARC / HOLDING_PATTERN：框住等待弧线或完整等待图形。若 holding 信息包括 inbound course、leg time、距离、turn direction，应尽量分别找到对应图形或文字证据。

            
DME_DISTANCE_TEXT：框住 20.5 DME、30.2、11.3 DME、5 NM 等距离文字。不要把距离和 fix 名称混成一个无法解释的大框。

            
可以确认的情况：框内能清楚看到目标值，且字段对应的航段、航段类型、字段名都正确。例如“航段 2 CF 的 Q1_fix_ident = MUDRE”，框里确实有 MUDRE。

            
不要确认的情况：框选到明显无关内容、目标文字不在框内、同一个符号被重复挂到不相干字段、航段编号不对、字段值和图上内容明显不一致。

            
重复框处理：如果同一个符号被多个框重复框到，保留最贴近、最清楚、字段对应最准确的那个；其他重复框可以不确认，必要时标记不确定或删除。

            
本图没有的字段：如果 canonical JSON 中该字段是 not_applicable、not_observable 或 unknown，通常不需要人工画框；它不会作为缺证字段要求你补框。

            
不确定时：不要硬凑。点“不确定”，备注原因，后续统一复核。宁可留下一个需要讨论的字段，也不要把错误证据保存成 accepted。

          


          

            
四、JSON 和评分怎么理解

            
页面里的 PR #28 对齐结果是“人工证据覆盖/证据对齐”，基准来自 CIFP/424 canonical JSON。

            
因为候选字段也来自 canonical target，所以这里不能当作独立模型正确率。真正实验正确率应使用独立 OCR/LLM 输出 JSON 去对比 canonical JSON。

            
not_applicable、not_observable、unknown、Q_terminator 等自动状态字段通常不需要画框；重点处理 present 且缺证的字段。
